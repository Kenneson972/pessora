Images produit — quelle architecture ?

Le champ image_url existe déjà en DB. Comment intégrer la galerie multi-images ?

A

Deux concepts séparés

image_url = image principale (hero, panier, carrousel)

gallery[] = images supplémentaires affichées en mini-grid sous le hero

+ Simple · aucune migration des données existantes
− L'admin gère deux zones d'upload distinctes

B

gallery[0] = image principale (avec sync image_url)

gallery[0] devient le hero. Le code met à jour image_url automatiquement pour le backward compat.

Une seule zone de gestion dans l'admin. La première image de la galerie est toujours le hero.

+ UX unifiée · backward compat transparente
− Un peu plus de logique de sync

C

gallery[] remplace image_url complètement

Suppression de image_url. Tout le code de lecture bascule sur gallery[0].

+ Architecture propre à terme
− Migration lourde, tous les fichiers qui lisent image_url à mettre à jour
